# Code Review — Phase 2: v1.1 "Atlas unblock + schema v2"

## Verdict

land, all 14 tasks are implemented, and the migration/atomicity test coverage is
genuinely strong. **905 of 906 tests pass** (the 1 failure is a pre-existing,
jitter-sensitive perf micro-benchmark unrelated to this phase).

**But the branch ships with red CI gates.** The plan's own Definition of Done
(plan §"Phase Deliverables", lines 568–570) promises `ruff check .`,
`ruff format --check .`, and `mypy --strict plumb/core/` all green. Three of those
fail on the **exact CI-scoped paths** (`.github/workflows/test.yml`). This is a
**blocker** — merge would go red.

Recommend: fix the four gate findings below (all mechanical, ~10 min), re-run the
suite, then merge.

## Findings (severity-ordered)

### 🔴 BLOCKER-1 — `mypy --strict plumb/core/` fails: `Span.attributes: dict` missing type args

`plumb/core/entities.py:145`

```python
attributes: dict | None = None
```

CI runs `mypy --strict plumb/core/` (test.yml:39). Under strict mode a bare `dict`
is `[type-arg]` error:

```
plumb/core/entities.py:145: error: Missing type arguments for generic type "dict"  [type-arg]
```

The same bare `dict` annotation appears in every downstream signature it flows
through — `api.py:39` (`_validate_attributes`), `api.py:305` (`add_span`), and
`storage_sqlite.py:229` (`_attributes_from_row`) — but only `core/` is under
mypy-strict in CI, so `entities.py:145` is the one that reddens the pipeline.

**Fix:** annotate as `dict[str, Any] | None` (add `from typing import Any` — already
imported nowhere in entities.py, so add the import). Propagate the same
`dict[str, Any]` to the three sibling signatures for consistency even though only
`core/` is gated, so a future `mypy plumb/` expansion doesn't re-surface it.

> **Judgment note:** `dict[str, Any]` matches the FR-ATTR-1 contract (JSON object →
> Python dict) and the `_attributes_from_row` guard already rejects non-dict JSON.
> `dict[str, object]` would be stricter but forces `cast`s at every read site — not
> worth it for an advisory attributes bag. Recommend `dict[str, Any]`.

## What's genuinely good (called out so it isn't lost in a fix pass)

- **Migration atomicity is correctly implemented and correctly tested.** The
  `BEGIN`/`try ALTER…/except ROLLBACK/else COMMIT` structure in
  `storage_sqlite.py:454-466` is right, and AC-MIG-4
  (`test_migration_failure_rolls_back_atomically`) proves it by asserting the
  *earlier-in-transaction* `rationale` column is absent after an injected
  index-creation failure — i.e. it verifies true single-transaction atomicity, not
  "mostly migrated". SQLite 3.46 makes `ALTER TABLE ADD COLUMN` transactional, so
  the assertion is sound. This is exactly the test that catches a partial migration.

- **Fresh-DB vs migrated-DB convergence** (`_bootstrap_schema:417` treating
  `version in (0, 1)` identically) is the right call — a brand-new DB and a
  migrated-from-v1.0 DB land on the same `user_version=2` shape. Cleanly avoids a
  second DDL path to keep in sync.

- **DATA-MIG-6 duplicate pre-check runs before any DDL and names every conflicting
  tuple** (`storage_sqlite.py:434-452`), zero deletions — the security/integrity
  posture the plan §Security demanded. Verified by AC-MIG-3.

- **`write_score` idempotency via `ON CONFLICT … DO NOTHING` + `rowcount==1`**
  return is clean, and the advisory-only `idempotency_key` is correctly `del`'d
  (not stored, not in the conflict target) with a docstring saying so — matches
  FR-IDEM-4. The CLI reports insert-vs-no-op (`cli.py:238-241`).

- **`resume_run` reuses the existing `finalize_run` UPDATE path** via the shared
  `_finalize_and_write` helper (api.py:491) — no duplicated close-out logic between
  `_RunFactory` and `_ResumeRunFactory`. The pre-yield `NotFoundError`/
  `ValidationError` raises correctly propagate (caller errors), while storage
  failures inside `_finalize_and_write` fail-degrade (NFR-Rel-1). Good separation.

- **`_attributes_from_row` never raises on read** (returns `None` on non-JSON or
  non-dict), matching FR-ATTR-3's "never raise on read" — and there's an explicit
  hand-corrupted-fixture test for it.

- **`FakeStorageWriter` and `_NoopStorageWriter` both fully implement the grown
  `StorageWriter` protocol** (`open_or_resume`, usage kwargs, `write_score` return
  bool) in the same commits — CLAUDE.md Rule #1 honored. `test_ports_compliance.py`
  guards it.

## Non-findings (checked, deliberately not flagged)

- **`PRAGMA user_version = N` inside the transaction** — journals and rolls back
  correctly under SQLite 3.46; AC-MIG-4 confirms `user_version` stays 1 after
  rollback. Not a bug.
- **`resume_run` + `set_usage` last-wins across the resume boundary** (FR-USAGE-4) —
  correct: a resumed run does not reload prior spans, so auto-fill only sees the
  resume session's buffer, and explicit `set_usage` overwrites. Tested at
  `test_set_usage_sqlite.py:140`. The 1-hour clock offset in that test sits exactly
  on the stalled-sweep boundary (`start_ts < now-3600s` is false at equality) so the
  resumed run survives the sweep — fragile-looking but correct. Worth a one-line
  comment in the test, not a blocker.
- **`stalled`-as-non-resumable** (Pending Decision 1) — implemented as recommended
  option (a); `status != PENDING` raises `ValidationError`. Consistent with the plan.
